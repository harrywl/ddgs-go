# Changelog

This Go port tracks the release cadence of the Python upstream
([deedy5/ddgs](https://github.com/deedy5/ddgs)): the version number is the
upstream version it is at parity with, suffixed with `-go.N` for the revision
of this port.

## 9.16.0-go.1 — 2026-10-19

First release at full parity with Python ddgs v9.16.0 (upstream HEAD
70a5635, 2026-08-26). Forked from dreamyang-liu/ddgs-go @ eda6e65, which had
ported the library core against upstream ~2026-07-30 (pre-v9.15.0).

### Engine parity (the drift the fork was created to close)

- **google text engine rewritten** for upstream 3ea6cbc (v9.16.0): switches
  from the desktop HTML endpoint to the WML endpoint
  `https://www.google.com/wml/search`, with the Nokia/UC Browser user-agent
  pool, the `div[./div[1]/a and ./div[2][table]]` item xpath, the
  `sca_esv=1` payload parameter, a raw (non-lowercased) region split for
  `hl`/`lr`/`cr`, and WML prolog pre-processing. The Python
  `find("?>") == -1` slicing quirk is reproduced deliberately and documented.
  Extraction goldens were generated by running Python ddgs 9.16.0 on the same
  fixture, so the two implementations are byte-identical on it.
- **yandex unregistered** from the text registry: upstream disabled it in
  f4ba66c (v9.15.0, 2026-08-16). The engine code is kept (mirroring upstream,
  which keeps the `disabled = True` class) but is no longer selectable, and
  `backend=yandex` now warns and falls back to auto like any unknown backend.
- **yahoo_news source separator** fixed to `U+00B7 + two spaces`
  (" ·  via Yahoo"), byte-exact with `yahoo_news.py::extract_source`. The fork
  had one space, so sources were never stripped.
- `TestRegistryMatchesPython` now asserts the registry matches upstream's
  dynamically built `ENGINES` dict in both directions (no extras, no omissions).

### Added

- **CLI** — `ddgs` binary with `version`, `text`, `images`, `videos`, `news`,
  `books`, `extract`, `mcp` and `api` subcommands, mirroring `ddgs/cli.py`
  flag-for-flag (repeatable `-b/--backend`, `-o/--output` csv/json,
  `-d/--download` with `-dd`/`-th`, `-nc/--no-color`, per-category filters).
- **HTTP API server** — `ddgs-api`, a stdlib `net/http` port of the FastAPI
  app: GET+POST `/search/{text,images,news,videos,books}`, GET+POST
  `/extract`, `/`, `/health`, with Pydantic-matching JSON field names and
  defaults (including the three-state `max_results`: omitted → 10, `null` →
  unlimited), the `{"detail": ...}` error shape, and a replica of Starlette's
  `CORSMiddleware` behaviour.
- **MCP server** — `ddgs-mcp`, a stdlib JSON-RPC 2.0 stdio server exposing the
  same six tools as `ddgs/api_server/mcp.py`.
- `ddgs.ResultFields(category)` — exported per-category field order (the
  Python dataclass field order) for CSV headers and stable output.
- `ddgs.Version` / `ddgs.LibraryVersion()` — `"9.16.0-go.1"`.
- `ddgs.ErrUnsupportedFormat` and the `FormatTextRich` constant.
- `Makefile` (build/test/lint/release with a cross-compile matrix) and GitHub
  Actions `ci.yml` (3 OS × go 1.25/1.27) + `release.yml`.
- `docs/` — the gap analysis, spec and execution plan behind this release.

### Changed

- `Extract` with `fmt="text_rich"` returns `ErrUnsupportedFormat` instead of
  silently falling back to markdown. `text_rich` is produced by primp's Rust
  extractor and has no pure-Go equivalent.
- Module path renamed to `github.com/harrywl/ddgs-go`.

### Intentional divergences from the Python implementation

Kept from the original fork and documented in `docs/SPEC.md` §9:

1. Streaming fan-out scheduler instead of wave-based `ThreadPoolExecutor`.
2. `minWorkersWithGeneral = 3` floor so a general SERP engine is always in
   flight alongside the single-result encyclopedia engines.
3. Per-engine failure cooldown (2 consecutive failures → skipped 5 min in
   auto mode).
4. `context.Context` as the first parameter of every public method.
5. `MaxResults: -1` spells Python's `max_results=None`.
6. `net/http` + a browser user-agent pool instead of primp's TLS/JA3
   impersonation — see Known limitations.
7. `text_rich` unsupported.
8. `ddgs api --reload` accepted but a no-op.

### Known limitations / future work

- **F1 — no TLS impersonation.** The Python client impersonates real browser
  TLS fingerprints via primp; this port cannot, so fingerprint-sensitive
  engines may rate-limit it sooner. The cooldown in (3) mitigates this.
  Evaluating `utls` is the tracked follow-up.
- **F2** — `ddgs api --reload` (needs fsnotify or a re-exec loop).
- **F3** — no `/docs`, `/redoc`, `/openapi.json` (FastAPI-generated).
- **F4** — packaging: Homebrew formula, AUR, vanity import paths.
